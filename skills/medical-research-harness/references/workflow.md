# 研究工作流与产物

只读当前阶段所需部分。阶段名称是工作顺序；机器检查仅验证文档证据的一致性，科学放行由批准协议和复核决定。

执行本工作流时读取 [operations.md](operations.md)，使用 plan / audit / preflight / summarize 命令。`check_bundle.py` 只做文档一致性；`study.py` 执行其中有明确输入契约的数据检查与运行对账。

## 1. design：研究设计与偏倚控制

读目标研究已有证据后，用契约固定研究问题、估计目标/预测目标、目标人群、实际可核验入组标准、结局、时间锚点、允许信息、主指标与验证设计。列出无法从数据核验的条件；不能根据疾病名称推断活动期或时点。

生成如下控制表，并把每行转成目标项目任务。下表是工程控制，不是官方 PROBAST 信号问题。

| 风险 | 要指导的数据/实验动作 | 验证设计与证据 |
|---|---|---|
| 选择偏倚与适用性 | 固定来源、人群、入组单位及排除时点；解释便利抽样 | 每步入组流图、未核验条件清单、来源/中心/时期聚合分布 |
| 患者与重复测量泄漏 | 根据目标锁定患者/会话分组；新患者外推与同患者未来预测分别设计 | patient/group 交集计数、重复记录归属；若允许患者跨时间分区，说明估计目标并审计严格时间顺序 |
| 时间与标签泄漏 | 区分事件发生、采集、结果发布和实际可用时间；固定预测锚点与标签窗口 | 可用时间违例、跨窗口重叠与标签污染计数；索引时点和结局算法单独核查 |
| 中心、来源及测试污染 | 固定各数据集用途、适配标签权限及最终测试暴露记录 | 中心/时期分离审计、测试访问记录；目标标签更新不能称无监督适配 |
| 填补与筛选泄漏 | 切分后在每个训练折拟合填补、编码、缩放、特征筛选和重采样 | 拟合样本归属审计；验证集/测试集只应用冻结变换 |
| 缺失与异常值偏倚 | 保存缺失/未知语义；核对单位和采集规则；禁止默认全量中位数填补或 IQR 裁剪 | 各分区缺失率、处置前后数量及临床依据；在开发数据预设敏感性方案 |
| 样本量与过拟合 | 依据事件率、任务复杂度、预期性能/估计精度及设计效应论证规模 | 样本量/精度依据；完整开发过程的内部重采样验证，调参在内部循环 |
| 结局和删失处理 | 固定定义、观察窗、判定方式、删失与竞争事件；诊断任务不套未来事件假设 | 标签定义复核、随访完整性及观测时间证据 |
| 乐观性能与不确定性 | 冻结模型、阈值、校准方法及指标；按相关性单位计算区间 | 内部/时间/外部结果分别列；判别、校准、整体误差和适用的临床效用指标 |
| 选择性报告与过度结论 | 预设主次指标、实验预算、敏感性和停止规则；记录所有尝试 | 登记与结果逐项对账；阴性/失败/中断及不支持结论保留 |

### 实验矩阵

每个实验填：`问题 / 确证或探索 / 数据与切分 / 基线与对照 / 唯一变化 / 指标与区间方法 / 预算、种子、停止条件 / 放行条件 / 产物 / 可支持结论`。

至少包含批准的主分析和必要内部验证；时间、中心或外部验证与拟外推场景相匹配。敏感性方案可针对缺失处置、标签不确定性、采集差异或组别稳定性，但只能改变协议预先允许的因素，不得为较好指标重选终点或验证集。

偏倚控制首先验证操作是否成立，例如训练折拟合审计、预测前可用性和分区交集。不要故意用泄漏数据训练对照来证明主分析有效。需要软件负例时在合成数据上检查拦截能力，不能把合成结果当作临床证据。

拟合与选择的经验步骤仅使用允许的开发分区。固定物理单位转换和批准的确定性入组规则可先执行；任何从分布或标签学习的步骤必须限于训练边界。仅在预先锁定的最终评价方案允许时计算测试标签上的指标与区间，不能用其反向选择模型或分析策略。

### 数据处理任务的最小格式

| 字段 | 要写的内容 |
|---|---|
| 输入 | 数据发布版本、契约、允许分区、字段与时间语义 |
| 操作 | 入组、单位核查、标签构造、特征可用性、切分、训练折拟合的实际顺序 |
| 命令 | 目标项目已有命令或需实现的最小入口；输出使用唯一 RESEARCH_RUN_DIR |
| 接受标准 | 违例计数、交集、缺失字段及预算上限；每个阈值来自协议 |
| 产物 | 聚合 QC、实现修订、切分身份、拟合边界与运行记录 |
| 偏离处理 | 明确停在哪一步、报告什么、何时需协议修订 |

若目标环境已配置 ResearchLab，复用其中的 `templates/task-specification.md`、`templates/scientific-review.md` 和 `tools/lab.py`。这些外部文件不随本包分发。先检查当前 runner 命令与既有登记，避免重复实验；其他环境按 operations.md 的接口接入自己的审批、锁和登记工具。

## 2. preflight：数据审计与执行前检查

在目标项目追踪一条代表性的实现路径，使用标识和代码定位进行核对，提示与共享报告仅含聚合计数。重点核对入组、预测锚点、允许字段、结局窗口、切分和拟合顺序。

输出至少包含：数据身份、字段字典、入组流图、时间/患者/中心/标签检查、缺失与异常值处置、切分身份、预处理拟合边界及未解决条件。`data_identity` 使用已有数据清单/发布身份文件，不把原始患者文件放入证据包。

即使技术检查成立，也要由科学批准判定是否可执行。确证性和探索性实验均需适用的科学批准、协议锁、可执行任务规格、运行登记、独占写入者及资源预算；已有批准沿用。首次尝试和失败重试均登记。不能因修复环境或填好模板就启动模型实验。

## 3. results：偏倚评估与结果汇总

先对账注册的全部尝试，再读取允许的聚合指标、日志和实现证据。每个尝试保留数据身份、代码修订及脏代码快照身份、协议锁、任务、切分、参数、种子、资源、产物、退出状态、偏离和局限。失败或未执行项必须显式占位，不能只保留最佳模型。

正式预测偏倚评估按 [methodology.md](methodology.md) 取得完整官方工具后逐题完成。工程证据为判断提供依据；不能从证据包通过推断低风险。单列开发质量、评价偏倚和适用性，并给出新的只读复核。

生成结果汇总中的四张表：

| 表 | 必需列 |
|---|---|
| 尝试对账 | attempt/run_id、协议版本、数据身份、代码/环境/参数身份、切分、种子、状态、偏离、产物 |
| 主要与敏感性结果 | 问题、确证/探索、模型/对照、验证类型、样本/事件分母、指标、区间、方法、状态、证据定位 |
| 偏倚与适用性 | 工具/版本/部分、模型/数据集、题目/域、答案、理由、证据定位、缺失信息、复核/裁决 |
| 结论边界 | 结论、支持证据、未解决风险、不可外推部分、是否通过科学复核 |

先解释研究问题是否被回答，再解释指标大小。不把关联称因果，不把预测称疗效，不把 AUC 称临床效用。对特定模型或数据集适用的判断不能外推到所有结果。

## 证据包的阶段角色

`format_version=1`，`study_id` 为非空标识，`phase` 是当前阶段，`artifacts` 是条目列表。每条包含 `role/status/path/sha256/locator/note`；状态允许 `available/planned/missing/not_applicable`。核心角色必须 `available`；可豁免角色也需要存在的理由文档、哈希、定位及 note。未到当前阶段的 planned/missing 条目不阻塞；任何已提供的 available/豁免文件都会核对完整性。

| 阶段 | 新增必要角色 | 内容与语义 |
|---|---|---|
| design | protocol、data_dictionary、bias_plan、analysis_plan | 草案可以通过文件检查，但批准状态仍是 DRAFT |
| preflight | approval、protocol_lock、task_spec、run_registration、data_identity、data_audit、split_audit、preprocessing_audit | 审批对应准确协议；锁与任务引用一致；审计满足协议边界 |
| results | run_record、metrics、bias_assessment、result_summary、independent_review | 全部尝试对账、聚合结果、完整逐题判断、结论边界、新的只读复核 |

阶段角色累积。仅 split_audit 和 preprocessing_audit 可以 `not_applicable`，例如无切分/无拟合的描述性分析，仍需审查依据。别的角色若暂时不能提供就检查失败并列缺证据；不把失败/缺失指标伪装成 metrics 成功结果，metrics 文档可明确说明该尝试失败且无估计。

同一文档可以承担多个角色，但不同职责需具体 locator。协议锁定后不继续往该文件追加结果；结果写入独立文件，免得改变批准版本的哈希。审批有效性、锁绑定、正文完整性、逐题集合、数据/运行一致性和科学有效性必须由 agent 与复核员另行核对，检查器不解析文档正文。
