# 分层研究 agent：实现与验证记录

## 目标与职责

现有 workflow.py 负责确定性研究检查；新增语义决策组件对显式提供的主张和证据片段进行结构化核验。语义组件为 shadow mode，不修改审批、协议或研究文件，不执行实验。

| 层 | 任务 | 输出与边界 |
|---|---|---|
| 程序 | 哈希、字段、出处定位、预算、输出验证 | 精确约束；不交模型猜测 |
| 轻量判断模型 | 窄范围证据支持关系 | supports / contradicts / insufficient；附已有证据定位 |
| 强推理模型 | 轻量判断不足、格式错误或证据核验失败后的复核 | 仍为建议，不产生科学接受 |
| 实现代理 | 按已授权任务补代码、整理证据 | 通过宿主工具和项目测试；不能由语义输出直接执行任意命令 |
| 独立复核 | 审查实现和最终证据 | 分开记录软件复核与科学接受 |

层级配置使用不同 provider/model 标识；角色名不同不证明底层模型不同。若供应商只返回别名，不能宣称独立权重或已固定实际版本。模型自报 confidence 不是经过验证的校准概率，升级阈值需在目标材料上评估。

## 初次连接核验

已通过 Hermes CLI 实际调用 `magpie / codex/gpt-6-astra`，限定无工具、单轮、合成连通性请求，获得 `{"status":"ok"}`。这只证明该请求可执行，不证明任务性能，也未验证供应商底层权重身份。

当前 auxiliary 配置没有指定独立轻量模型。直接读取提供商模型目录超时；后续从非敏感模型缓存取得原始 ID `gpt-5.6-luna`，真实请求超时，未证明其可用性或轻量程度。没有读取凭据文件或将研究材料外发。后续模型接入状态与实际执行结果分别登记，不把模拟 adapter 测试当成真实模型实验。

## 本轮实现与验证结果

已实现 decision_agent.py、hermes_decision_adapter.py、策略模板及操作文档 decision-agent.md。通用语义组件有两层显式配置、有限升级、逐字引文检查、输入/输出限额、批准对 cases/policy 的规范化哈希绑定和失败报告；Hermes adapter 在 Linux 上预防性禁用工具并清理进程，依赖已安装 Hermes 的内部接口，接口缺失则拒绝。`-t ''` 会回退默认工具，前述初次连通性仅由提示禁止工具，不能算预防性隔离；当前适配器已替换该方法。

父代理重新执行整个 CLI 链路，`build/agent-final-live/output/decision.json` 返回 supports、有效引文、request_count=1、exit_code=0。使用的是 magpie / codex/gpt-6-astra 放在首层插槽，不是轻量模型实测或双模型验证；model 字段也不是独立供应商权重证明。记录仅含合成研究陈述。

最终本地测试：decision_agent 21 项、Hermes adapter 12 项、workflow 18 项、study 24 项及文档检查通过；公开回归 76 项通过（build/agent-final-regression），git diff --check 通过。独立审查发现的极大整数溢出、无界输出和外发未绑定问题已修复并纳入测试。尚未完成目标医疗任务性能评估、真正双模型实测或 Jev 接入。


## 验证要求

输入限定显式选定的材料；真实材料外发需有适当授权，不自动读取项目患者数据。命令适配器为本机可信程序接口，不是沙箱；以 argv 调用、stdin 传结构化请求，禁止 shell 拼接。保留请求上限、超时、模型身份、输入和策略哈希、每次尝试状态；原始错误或模型正文不进入共享诊断。

软件测试覆盖格式错误、未知标签、伪造出处、逐字引文不匹配、证据不足、无配置、预算耗尽、超时和服务失败。模型效果另需按研究项目或论文划分的专家标注集，比较纯规则、单模型和分层模型的错误放行、漏检、弃权、成本和延迟。独立多上下文代理不等同于不同模型实测。
